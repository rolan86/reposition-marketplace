# reposition-onboard

**REPOSITION Onboarding Accelerator** — learn any codebase and ship your first contribution on day 1.

## What It Does

You just cloned a repo you've never seen before. Instead of spending weeks reading docs and asking colleagues, you install this plugin and point it at the codebase. It scans the project (tech stack, structure, patterns, conventions, git history, tests, CI/CD), then offers two ways to learn:

- **Guided Tour** — Walk through architecture, patterns, conventions, and a deep dive into your work area, then ship a first contribution
- **Open Explore** — Quick orientation, then you drive: ask anything about the codebase, drill into modules, trace flows, compare patterns

Both paths end with a guided first contribution and a personal onboarding doc saved for your reference.

**Time:** 30-60 minutes for a full onboarding session. `/reposition-ask` for quick follow-up questions anytime.

## Installation

First, add the REPOSITION marketplace (one-time setup):

```bash
claude plugin marketplace add /path/to/REPOSITION/developer-track/plugins
```

Then install the plugin:

```bash
claude plugin install reposition-onboard
```

Uninstall:

```bash
claude plugin uninstall reposition-onboard
```

## Commands

| Command | Description |
|---------|-------------|
| `/reposition-onboard` | Full onboarding: scan the repo, choose guided or explore mode, learn the codebase, ship your first contribution |
| `/reposition-ask` | Quick Q&A: load a previous scan and ask questions about the codebase without re-running the full flow |
| `/reposition-contribute` | Jump to contribution: load a previous scan and get guided help shipping a task |

## How It Works

### 1. Scan (automatic)

The plugin scans 10 signals from your codebase:

| Signal | What It Detects |
|--------|----------------|
| Tech stack | Language, framework, build tool, top dependencies |
| Project structure | Monolith, monorepo, microservice, library |
| CLAUDE.md | Existing conventions and workflow rules |
| Git history | Commit count, contributors, branch/commit conventions |
| Documentation | README, CONTRIBUTING, ADRs, docs directory |
| Test patterns | Framework, coverage, test organization |
| CI/CD | Platform, workflow names |
| Entry points | API controllers, CLI commands, main files |
| Key abstractions | Interfaces, base classes, middleware, utilities |
| Environment | Docker, .env.example, run instructions |

### 2. Choose Your Mode

> **A) Guided tour** — I walk you through everything step by step
>
> **B) Open explore** — I give you the lay of the land, then you drive

### 3. Learn

**Guided Tour (4 phases):**
1. Architecture overview — system type, directory map, data flow, dependencies, how to run
2. Patterns & conventions — code style, architecture patterns, testing, git workflow, unwritten rules
3. Deep dive — pick your work area, trace execution paths, see recent changes, learn gotchas
4. Contribute — ship your first PR

**Open Explore:**
- Condensed orientation, then free-form Q&A
- Ask about architecture, trace flows, drill into modules, compare patterns, check history
- Guard rails nudge you to check testing/git conventions before contributing

### 4. Contribute

- Bring an assigned task or let the plugin suggest a good starter (TODOs, test gaps, open issues)
- Plan-first approach with codebase-aware pair programming
- PR readiness check against detected conventions

### 5. Save

Personal onboarding doc saved to `.reposition/onboarding-YYYY-MM-DD.md` — your reference for this codebase.

## Works Standalone

No setup required. No team lead configuration needed. Point it at any repo and go.

If the repo has a CLAUDE.md (e.g., generated by `reposition-transform`), the plugin uses it directly — bonus head start, not a requirement.
